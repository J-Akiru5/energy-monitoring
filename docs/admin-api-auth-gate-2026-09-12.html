What Changed

Every admin API route that previously had zero authentication now performs its own server-side session check and permission gate, independent of the (non-functional) proxy.ts middleware. The relay routes were refactored from a proxy-to-web-app pattern to direct @energy/database calls with full customer scoping.

Auth Pattern

Every route now follows the same pattern established in apps/web/src/app/api/devices/route.ts:

1. cookies() → createClient(cookieStore) → supabase.auth.getUser()
2. If no user → 401 "Not authenticated"
3. resolveAccess(user.id, "<permission>") → customerId
4. If AccessDeniedError → 403 with err.message
5. (For scoped routes) lookupControllerByDevice(deviceId) → verify stamp.customerId === customerId
6. If mismatch → 403 "Device not found or access denied"

Relay Refactor Detail

The relay routes were the biggest structural change. Previously:

  • GET /api/relay proxied to apps/web's GET endpoint with no auth forwarded (always got 401 upstream)
  • POST /api/relay proxied to apps/web's POST endpoint, attaching RELAY_ADMIN_SECRET header server-side

Now:

  • Both routes call @energy/database functions directly (getRelayState, updateRelayState, getRelayConfig, logRelayAction)
  • Both routes perform session auth + resolveAccess(userId, "control_relay")
  • Both routes verify device ownership via lookupControllerByDevice
  • RELAY_ADMIN_SECRET forwarding removed — real auth replaces shared-secret proxy trust
  • Super Admin bypass works via SUPER_ADMIN_CUSTOMER_ID sentinel ("*")
