5. Backfill Script Logic

What it does (runtime query, not hardcoded)

  1. Ensures pgcrypto extension is available
  2. Creates Customer: "Western Visayas State University" (type=ORGANIZATION, status=ACTIVE)
  3. Creates Site: placeholder "WVSU Main Campus" (Jeff must confirm)
  4. Creates Building: "CICT Building"
  5. For EACH row in devices (queried at runtime):
    • Creates EMU with label = devices.name
    • Creates Controller with token_hash = SHA-256(devices.api_key_hash) and legacy_device_id = devices.id
    • Creates Installation linking EMU to CICT Building
    • Creates EMU Configuration with phase_mode = THREE_PHASE
  6. Stamps all existing rows in: power_readings, alerts, relay_logs, blackout_events, device_alert_state
  7. Logs verification counts at the end

Why the script can't report actual row counts here

Supabase CLI and Docker are unavailable in this environment. The script queries the live database at runtime. Actual before/after counts will only be visible after supabase db push runs against the real project.

6. Ingest Route Changes

// After existing device auth succeeds:
const tenantStamp = await lookupControllerByDevice(device.id);

// Pass to insertReading (graceful if null):
await insertReading(serverPayload, tenantStamp);

Behavior: If controllers.legacy_device_id matches the authenticated device, the stamp (customer_id, emu_id, installation_id, controller_id, phase_config) is written to the new columns on power_readings. If no match exists (pre-backfill or orphaned device), the insert proceeds without the new columns — telemetry ingestion never breaks.
