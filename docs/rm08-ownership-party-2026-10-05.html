The gap RM-08 closes

Decisions #1–#3 assume a checkable fact about hardware: does Syntaxure or the customer own this unit? The schema could not express it. emus.owner_type holds 'CUSTOMER' | 'SITE' | 'BUILDING' — which level of the org tree an assignment targets. Redefining that column was rejected (OD-1) because anything reading it as assignment granularity would break silently.

Repo check before the change: no application code reads owner_type at all — only the schema, the phase-3a backfill, and RLS test fixtures reference it. The additive column is therefore zero-risk to existing readers, and ownership_party is now the one place ownership lives.

Migration & safety

supabase/migrations/20261005000000_rm08_ownership_party.sql — the safe additive pattern:

ALTER TABLE emus ADD COLUMN IF NOT EXISTS ownership_party TEXT;
UPDATE emus SET ownership_party = 'CUSTOMER' WHERE ownership_party IS NULL;
ALTER TABLE emus ALTER COLUMN ownership_party SET DEFAULT 'CUSTOMER';
ALTER TABLE emus ALTER COLUMN ownership_party SET NOT NULL;
COMMENT ON COLUMN emus.ownership_party IS '...';
  • Nullable add → backfill → NOT NULL — no table rewrite, and existing rows are provably populated before the constraint lands.
  • Idempotent — IF NOT EXISTS, WHERE ... IS NULL, and re-runnable SET DEFAULT/SET NOT NULL.
  • Backfill = 'CUSTOMER' — every EMU that exists predates provider-owned hardware (the WVSU pilot and all test fixtures were provisioned for their customer).
  • No CHECK constraint — matches house style (value domains documented in comments; see owner_type, status, phase_mode).

No app code, types, or queries changed: packages/types has no EMU type, and nothing reads the column yet. RM-09 is its first consumer.
