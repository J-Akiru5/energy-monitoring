Was admin's proxy.ts ever non-functional?

RM-13 — closed. No. Admin's session proxy has been correctly wired since March 2026 (Next.js 16's proxy.ts convention) and is executing today — observed directly during the 2026-10-04 staging validation, where unauthenticated admin requests were redirected to /login by it. The "non-functional proxy.ts middleware" phrase in commit 5c9f6cf's message was an overstatement: the proxy does its job (session redirect), but a session middleware cannot perform per-route permission and ownership authorization — which is what that commit's per-route gates were actually for.

If the proxy had truly been non-functional, those admin API calls would have reached the route handlers and returned their own 401 {"error":"Not authenticated"} JSON — they did not.

Why "non-functional" appeared

The 2026-09-11 staging-validation procedure asserted "no middleware.ts file to wire it up" for the admin app — an assumption from pre-Next-16 convention. Next.js 16 renamed the convention to proxy.ts; the admin app had already migrated in March. This is the same error class already recorded in the architecture doc's risk register: a "dead code" finding re-asserted as confirmed before someone checked the file and found the rename. The commit message inherited the stale premise.

Lesson

"Can't authorize APIs" ≠ "non-functional"

The proxy's real limitation — a session redirect cannot enforce per-route permissions or device ownership on JSON APIs — is exactly why the per-route gates were required. That's a design boundary, not a defect. The wording in the commit overstated a true limitation into a false claim about the file.

Residual note

One genuine behavior question remains from the staging validation (Finding B there): unauthenticated /api/* calls on non-exempt paths get a 307 redirect to an HTML login page rather than a 401 JSON — awkward for API clients, though access is correctly denied. That is a deliberate-change candidate for the middleware (return 401 JSON for /api/*), not part of this finding.
