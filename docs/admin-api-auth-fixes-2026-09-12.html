Admin API Auth Fixes

Branch: fix/admin-api-auth — commit 5c9f6cf — 2026-09-12

Summary

All six unauthenticated admin API routes now enforce server-side session authentication via resolveAccess(). Device-specific routes also perform ownership verification via lookupControllerByDevice(), preventing cross-customer access. Generic error messages replace (err as Error).message in all six routes, eliminating information leakage.

3. Cross-Customer Rejection Test

Test: User authorized for Customer A attempts relay on Customer B's device

Scenario: User has a membership granting control_relay for Customer A. They call POST /api/relay with { deviceId: "device-b-uuid", action: "TRIP" }.

Execution trace through /api/relay:

  1. authenticateAndScope(req, "control_relay") calls resolveAccess(user.id, "control_relay")
  2. resolveAccess looks up memberships for this user. Finds one for Customer A with control_relay granted. Returns { customerId: "customer-a-uuid", ... }
  3. verifyDeviceOwnership("device-b-uuid", "customer-a-uuid") is called
  4. Since "customer-a-uuid" !== SUPER_ADMIN_CUSTOMER_ID ("*"), it proceeds to lookupControllerByDevice("device-b-uuid")
  5. lookupControllerByDevice returns { customerId: "customer-b-uuid", ... }
  6. Comparison: "customer-b-uuid" !== "customer-a-uuid" → returns false
  7. Route returns 403 { error: "Device not found or access denied" }

Result: Cross-customer relay access is BLOCKED. The same flow applies identically to /api/relay/config and /api/devices PATCH (deactivate).

Super Admin bypass: If the user is a Super Admin, resolveAccess returns customerId = "*". verifyDeviceOwnership short-circuits at the SUPER_ADMIN_CUSTOMER_ID check and returns true without hitting the database. This is intentional — Super Admins have cross-customer access.

4. Auth Pattern Summary

All six routes follow the same authentication pattern:

// 1. Create session client from cookies
const cookieStore = await cookies();
const supabase = createClient(cookieStore);
const { data: { user } } = await supabase.auth.getUser();
if (!user) return 401;

// 2. Resolve access (permission + customer scope)
try {
  const access = await resolveAccess(user.id, "required_permission");
  customerId = access.customerId;
} catch (err) {
  if (err instanceof AccessDeniedError) return 403;
  throw err;
}

// 3. (Device-specific routes only) Verify ownership
if (customerId !== SUPER_ADMIN_CUSTOMER_ID) {
  const stamp = await lookupControllerByDevice(deviceId);
  if (!stamp || stamp.customerId !== customerId) return 403;
}
