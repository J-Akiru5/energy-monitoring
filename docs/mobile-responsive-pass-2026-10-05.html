All pages are mobile responsive

Every page in apps/admin, apps/web, and apps/super-admin now renders without horizontal overflow from 320 px up. Admin — the app in the reported screenshot — gained a hamburger top bar and slide-in navigation drawer, because below 960 px its fixed sidebar previously just disappeared with no replacement.

TL;DR

  • Admin: new AdminShell — mobile top bar, slide-in drawer with the existing grouped nav, overlay, Escape/close, and sign-out; login no longer inherits the 276 px sidebar margin.
  • Admin: tables scroll inside their panels, alert rows and checkbox/button rows wrap, stat cards go 2-up, and the Reports page’s chart/filter CSS was repaired (a malformed nested block had disabled it on all viewports).
  • Web: inline gridTemplateColumns removed from phases/sensors/relay so the existing breakpoints apply; history page segmented control no longer overflows.
  • Verification: prerendered markup + Chrome DevTools device emulation at 320/375/768 px; scrollWidth == clientWidth on every page (measured with the overflow guard disabled).

What was broken

  • No mobile navigation in admin. .sidebar{display:none} below 960 px (globals.css) left phones with page content only — no way to reach another page except typing URLs.
  • Dead CSS block. Reports selectors (.report-chart-height, .reports-filter-row, .report-empty, accent helpers) were accidentally nested inside .sidebar-nav, so the Reports chart wrapper had no height and filters rendered unstyled on desktop and mobile.
  • Tables crushed instead of scrolling. Sensors (6 cols), relay logs (6 cols), and thresholds (3 cols) had overflowX:auto wrappers but no min-width strategy, so columns squeezed and action buttons compressed.
  • Non-wrapping flex rows. Alert items (icon + long mono timestamps + Dismiss), relay checkbox rows with long explanatory text, and the PZEM auto/manual + source buttons all overflowed at 320–375 px.
  • Inline grids defeating media queries in web. dashboard/phases, sensors, and relay carried inline repeat(3,1fr) / repeat(4,1fr) / gridColumn:"span 2" that overrode the 900/768 px breakpoints. History’s metric segmented control couldn’t shrink below four button min-contents (~91 px each) and pushed the page to 394 px wide at a 320–375 px viewport.

Verification

Each app was built for production, then its prerendered HTML was loaded in headless Chrome with CDP device-metrics emulation at 320, 375, and 768 px. The probe force-enables body{overflow-x:visible} before measuring so the overflow-x:clip guard could not mask real overflow, then compares documentElement.scrollWidth to clientWidth and flags any element extending past the viewport outside a scroll container.
