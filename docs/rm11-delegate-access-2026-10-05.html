Reusing the foundations

The schema already contained the concept — unused since phase 3a. memberships.is_external marks a contractor/external auditor, and membership_scopes holds per-membership scope rows, with the intended semantics documented in roles.ts: "absence of scope rows = customer-wide access." What did not exist anywhere was duration. Rather than inventing a parallel delegate table, RM-11 wires these up and adds the missing piece.

Design — scope & duration

  • Duration: expires_at on the grant itself. resolveAccess() filters expired grants out — an expired control_relay simply doesn't resolve, so AccessDeniedError fires. Invalid dates fail closed too (treated as expired, never as eternal).
  • Scope: non-empty membership_scopes restricts the membership to those targets; empty = customer-wide. Enforced by a new assertDeviceInScopes() helper using the tenant stamp — which now also carries the current installation's site_id/building_id so site/building scopes resolve.
  • Fail-closed by construction: a device that cannot be resolved to a stamp is denied for scoped callers, not allowed.
  • Explicit authorization: the delegate path is just a normal membership + grant — created by the customer's Owner through the same permission model, no new grant ceremony.
