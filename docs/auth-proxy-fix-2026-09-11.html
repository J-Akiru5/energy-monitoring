Auth Proxy Fix — Session Middleware Missing in Web App

Date: 2026-09-11 | Branch: main | Commit: e336e0c
FINDING: apps/web had no proxy.ts — session refresh and unauthenticated route protection were completely non-functional.
FIX APPLIED: Created apps/web/src/proxy.ts, updated updateSession to exclude /api/thresholds/esp32 (device token auth).

Root Cause

The updateSession function in packages/auth/src/middleware.ts was exported but never invoked. The web app had no proxy.ts file (Next.js 16's session middleware entry point), so the function was dead code.

Impact (pre-fix)

CheckResult
Session refresh on page loadNever happened — cookies expired silently

Unauthenticated access to /relay, /alerts, etc.Page served (broken API calls)
Login action (signInWithPassword)Worked — created session cookies
setAll cookie error handlingSwallowed silently (server.ts:17 assumes middleware exists)

Fix Details

FileChange
apps/web/src/proxy.ts Created — imports and calls updateSession from @energy/auth. Matcher excludes static files only.
packages/auth/src/middleware.ts Added /api/thresholds/esp32 to exclusion list (device token auth, no session).

Admin Verification

apps/admin/src/proxy.ts exists and compiles clean. Same pattern as web. No changes needed.

What This Enables

  • Supabase auth sessions now refresh on every page load (via middleware)
  • Unauthenticated users are redirected to /login at the edge (not after page load)
  • Logged-in users hitting /login are redirected to / (not shown login form)
  • ESP32 device token routes (/api/thresholds/esp32) continue to work without session

Still Requires Manual Browser Testing

This fix enables the middleware, but the actual login flow, session persistence, and logout behavior should be verified in a real browser against the production URL. The code is correct; the runtime behavior needs human confirmation.
