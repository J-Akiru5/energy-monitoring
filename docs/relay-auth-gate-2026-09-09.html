Relay Auth Gate — Security Fix Report

SECURITY fix/relay-auth-gate 2026-09-09

1. Problem

Severity: High — Unauthenticated remote relay actuation

POST /api/relay on the web app had zero authentication. Anyone who knows or guesses a deviceId UUID can remotely TRIP or RESET the physical relay controlling mains AC power. CORS was wide open (Access-Control-Allow-Origin: *), meaning the endpoint was callable from any origin, including a malicious page visited by someone on the same network.

This is a WVSU capstone project being delivered to an external client on Friday 2026-09-12. If the app is hosted on any reachable domain, this is a real safety exposure — not theoretical.

2. Solution

A shared-secret gate scoped exclusively to the actuating POST handler.

  • POST /api/relay now requires an X-Relay-Secret header matching the RELAY_ADMIN_SECRET environment variable.
  • Requests missing or mismatching the header receive 401 Unauthorized before any relay state is read or changed.
  • CORS Access-Control-Allow-Headers narrowed to only Content-Type and X-Relay-Secret (previously listed 9 unused headers).
  • Admin dashboard routes through a new thin same-origin proxy that attaches the secret server-side, so it never reaches the browser.
  • Web app's own relay page fails gracefully — buttons are disabled with an inline "Manual control temporarily unavailable" message.

5.2. apps/admin/src/app/api/relay/route.ts (new)

import { NextRequest, NextResponse } from "next/server";

export const dynamic = "force-dynamic";

const WEB_RELAY_URL =
  process.env.WEB_RELAY_URL ??
  "https://energy-monitoring-web.vercel.app/api/relay";

/**
 * POST /api/relay
 * Thin same-origin proxy: forwards relay commands to web's POST /api/relay,
 * attaching the shared secret server-side so it never reaches the browser.
 * Inherits Supabase session gating from proxy.ts's matcher automatically.
 */
export async function POST(req: NextRequest) {
  const secret = process.env.RELAY_ADMIN_SECRET;
  if (!secret) {
    console.error("[admin /api/relay] RELAY_ADMIN_SECRET env var is not set");
    return NextResponse.json(
      { error: "Server misconfigured" },
      { status: 500 }
    );
  }

  try {
    const body = await req.json();

    const upstream = await fetch(WEB_RELAY_URL, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "X-Relay-Secret": secret,
      },
      body: JSON.stringify(body),
    });

    const data = await upstream.json();
    return NextResponse.json(data, { status: upstream.status });
  } catch (err) {
    console.error("[admin /api/relay] Proxy error:", err);
    return NextResponse.json(
      { error: "Failed to reach relay service" },
      { status: 502 }
    );
  }
}

7. Request Flow (after fix)

Browser (admin dashboard)
  │
  ├─ GET  /api/relay/config?deviceId=...  →  admin's own DB route (no change)
  ├─ GET  /api/relay?deviceId=...         →  web's /api/relay GET cross-origin (no change)
  └─ POST /api/relay                      →  admin's POST /api/relay proxy
                                              │
                                              ├─ Adds X-Relay-Secret header server-side
                                              └─ Forwards to web's POST /api/relay
                                                    │
                                                    ├─ Validates X-Relay-Secret
                                                    ├─ Rejects 401 if missing/wrong
                                                    └─ Executes relay command if valid

Browser (web consumer app)
  │
  ├─ GET  /api/relay?deviceId=...         →  web's /api/relay GET (no change, open)
  └─ POST /api/relay                      →  web's POST /api/relay
                                              │
                                              ├─ Validates X-Relay-Secret
                                              ├─ Rejects 401 (no secret from browser)
                                              └─ Web page shows "Manual control temporarily unavailable"

8. Deployment Checklist

  1. Generate a strong random secret (e.g. openssl rand -hex 32)
  2. Set RELAY_ADMIN_SECRET in both Vercel projects (web + admin) with the same value
  3. Optionally set WEB_RELAY_URL in admin if not deploying to the default Vercel URL
  4. Redeploy both apps
  5. Verify admin dashboard relay trip/reset still works against a real or mocked device
  6. Verify web app relay page shows "Manual control temporarily unavailable" when in manual mode
