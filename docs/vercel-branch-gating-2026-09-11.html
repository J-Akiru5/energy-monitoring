1. Problem Statement

Every branch pushed to origin triggered a full Vercel preview deployment for all three apps (web, admin, super-admin). The existing turbo-ignore setup correctly gates builds per-app based on which files changed, but has no concept of which branch it is on. A feature branch that touches shared packages would still deploy all three apps.

3. Implementation

New File — scripts/vercel-ignore.sh (mode 755)

A single POSIX shell script at the monorepo root, called by each app's ignoreCommand. Accepts the turbo-ignore filter as $1. 

#!/bin/sh
# Vercel Ignored Build Step — energy-monitoring monorepo
# Exit codes: 0 = skip build, non-zero = proceed with build

ALLOWED_BRANCHES="main staging develop"
BRANCH="$VERCEL_GIT_COMMIT_REF"

case " $ALLOWED_BRANCHES " in
  *" $BRANCH "*)
    # Allowlisted branch — delegate to turbo-ignore for per-app change detection
    echo "Branch '$BRANCH' is in the deploy allowlist — running turbo-ignore for $1"
    npx turbo-ignore "$1"
    ;;
  *)
    # Non-allowlisted branch — skip unconditionally
    echo "Skipping build: branch '$BRANCH' is not in the deploy allowlist ($ALLOWED_BRANCHES)"
    exit 0
    ;;
esac

Modified Files — vercel.json in each app

apps/web/vercel.json
"ignoreCommand": "npx turbo-ignore web" → "sh ../../scripts/vercel-ignore.sh web"
apps/admin/vercel.json
"ignoreCommand": "npx turbo-ignore @energy/admin" → "sh ../../scripts/vercel-ignore.sh @energy/admin"
apps/super-admin/vercel.json
"ignoreCommand": "npx turbo-ignore @energy/super-admin" → "sh ../../scripts/vercel-ignore.sh @energy/super-admin"
Path Convention
The ../../ prefix matches the pattern already established by installCommand and buildCommand in apps/admin/vercel.json — each app's Vercel Root Directory is apps/<name>, making ../../scripts/ the correct relative path back to the monorepo root.

5. Environment Variable Confirmation

✓ VERCEL_GIT_COMMIT_REF — Confirmed Available at Ignored Build Step

VERCEL_GIT_COMMIT_REF is a documented Vercel system environment variable set to the branch name at Ignored Build Step evaluation time. It is available before the build starts, making it the correct variable to use for branch-level gating in ignoreCommand scripts. Reference: Vercel System Environment Variables.

⚠ Edge Case — "mainline" or "staging-hotfix" prefix
The case pattern uses space-delimited matching (" $BRANCH ") to prevent partial matches. A branch named mainline or staging-old does not match and will be correctly skipped. Only exact matches of main, staging, and develop are allowed through.

7. How to Add a New Pipeline Branch

If a new long-lived branch needs Vercel deployments (e.g., a release/v2 branch), update the single ALLOWED_BRANCHES variable in scripts/vercel-ignore.sh: 

# Before
ALLOWED_BRANCHES="main staging develop"

# After
ALLOWED_BRANCHES="main staging develop release/v2"

No changes to any vercel.json file are needed — it's a single-point-of-truth config.
