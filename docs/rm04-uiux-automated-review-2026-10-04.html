RM-04 — Automated UI/UX Review (WCAG 2.2 AA)

RM-04 advanced to its automatable limit. A real browser (system Chrome, driven by Playwright) walked the staging deployments: all three apps' login pages, the web dashboard, and the logout flow — both themes, with axe-core running the WCAG 2.2 A/AA rule set. Method

  • Browser: installed Chrome via Playwright's channel: "chrome" (the Chromium download was blocked; the system browser avoids it).
  • Rules: axe-core with the wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa tag set, injected into each page.
  • Environment: the staging deployments behind Vercel Authentication, reached with per-project automation bypass secrets; authenticated screens used a real SSR session cookie for the disposable fixture user.
  • Beyond axe: keyboard focus walk (first 8 stops, computed focus indicator), pointer-target sizes (in-viewport, < 24 CSS px), and 320 px reflow (no horizontal overflow).
  • Coverage limits: automated tooling cannot judge screen-reader phrasing, motion comfort, or visual intent; the super-admin landing page needs a super-admin session (no fixture exists, and creating one is a live DB mutation outside this task's scope).

Findings & fixes

S2 — serious

Login supporting text at 2.54:1 (WCAG 1.4.3)

#475569 on #0A0E1A at 12 px, on every app's login page. Fixed to #94A3B8 (7.5:1) in packages/ui/src/LoginForm.tsx; the same color on the AuthSplitLayout footer was fixed for consistency.

S2 — serious

Invalid definition-list semantics (WCAG 1.3.1)

The login feature list wrapped each <dt> in an inner div, so axe reported definition-list + 4× dlitem — screen readers could not announce the pairs as a list. Restructured in packages/ui/src/AuthSplitLayout.tsx so each card div directly contains its <dt> (icon + title in one flex dt) and <dd>.

S3 — minor

Dashboard ALERTS header link: 347×18 target (WCAG 2.5.8)

The panel header "Alerts" is a link to /alerts styled as a 12 px label with no padding. Added minHeight: 24 + 3 px vertical padding in apps/web/src/app/dashboard/page.tsx. The spacing exception likely applied before, but the explicit target size removes the judgment call.

Fix commit: 3166400 (PR #35 → develop → staging → main). Verified locally with the same axe rule set before deploying, then on staging after.

Pipeline notes (found while promoting)

Operational

Rapid same-SHA pushes can skip a staging deployment

Promoting by pushing the identical merge SHA to develop then immediately to staging/main hit Vercel's duplicate-commit handling: cfba894 produced only a develop deployment, so the staging aliases kept serving the previous build until they were repointed to the identical-SHA deployment. The admin project built a normal main deployment; web and super-admin needed alias repoints. Fix for next time: after each promotion, verify a deployment exists for the target ref (Vercel API) rather than assuming the push deployed — or space the pushes out.

Operational

Free-tier API deployment limit reached

vercel promote and API deployment creation both returned 402 (api-deployments-free-per-day, 100/day) — alias assignment still works, which is how the staging/production aliases were corrected. Worth knowing before relying on promote/redeploy during a release day.
