Overview now reports live system status

The admin Overview page hardcoded “Online” and counted every enabled device as an “Active Sensor”, so a powered-off system still looked healthy there while /sensors and /pzem correctly showed it offline. Both cards now derive from live telemetry using the same clock as the Sensors page and the DEVICE_OFFLINE alert.

TL;DR

  • System Status is now Online only when at least one sensor has recent telemetry; otherwise Offline in rose.
  • Active Sensors counts live (online) devices, not the is_active enable flag.
  • Freshness: the Overview polls /api/overview every 15 seconds, matching the Alerts page cadence.
  • No drift: status derivation moved into one helper (src/lib/liveStatus.ts) used by both routes.

Root cause

  • apps/admin/src/app/page.tsx rendered {"{loading ? \"—\" : \"Online\"}"} — the System Status value was a literal, never read from the API.
  • /api/overview returned activeDevices: devices.length, and listDevices() filters on devices.is_active (the enable flag), not on telemetry recency. A powered-off PZEM stays is_active = true, so it was counted as an active sensor.
  • The page fetched once on mount and never refreshed, so even a correct value would have gone stale when the site powered down.
